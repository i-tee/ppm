## Правила сессии

- Одна сессия, **без суб-агентов**. Большие файлы читай фрагментами.
- **Git-мутаций не делаешь** (add/commit/switch/stash). Read-only
  `git status/diff/log` – можно.
- Репо в WSL: `~/dev-partner`. Команды – через
  `wsl -d Ubuntu-22.04 bash -lc '...'`, не Windows-git по UNC (CRLF).
  Команды с кавычками или `$` – в `.sh`-файл в `/tmp` WSL, после удалить.
- ☠️ **Получил отказ в разрешении (permission / классификатор) – остановись
  и напиши об этом в отчёте. Не обходи другим способом.**
- Меняешь **только фронт** (`resources/js/`, `locales/*.json`) +
  `package.json`/`package-lock.json` (два пакета ниже). Сервер, роуты,
  миграции – не трогать.
- Вне задачи не чинить – найденное в отчёт.
- Тексты – через i18n (`ru.json` и `en.json`), «Avicenna®», тире «–» (не
  «—»), на «вы». Комментарии в коде – по-русски.
- Стек: Vue 3.5, Pinia 3 (другие геттеры – через `this`), vue-router 4,
  Vuestic UI 1.10. Сверяйся с версиями в `package.json` и документацией
  **этих** версий.

Прочитай `docs/cabinet-map.md` §1, §2, §5 (решение 4). Экран «Статистика»

Что есть в ответе (проверено на локалке):
- `credits.orders[]` – оплаченные заказы по промокодам партнёра, старый
  сайт (Joomla) и новый (`source: 'backend'`). Нужные поля:
  `order_date` (Joomla – строка `YYYY-MM-DD HH:MM:SS`; у заказов нового
  сайта формат может отличаться – парси оба, проверь), `cashback`
  (начисление партнёру, строка-число), `order_total`, `coupon_id`,

- ⚠️ В строках заказов сейчас лишние поля покупателя (ФИО, email,
  телефон, адрес) – **не используй их**, скоро сервер перестанет их
  отдавать (отдельный этап). Бери только поля из списка выше.

## Что сделать

### 1. Статистика (п. 3 карточки)

- Пакеты: `chart.js` + `vue-chartjs` – актуальные стабильные версии,
  совместимые с Vue 3 (проверь peer-зависимости). Ставить в контейнере:
  `docker exec laravel_node npm install chart.js vue-chartjs` – чтобы
  обновился `package-lock.json` (на проде `npm ci`). Регистрируй в
  Chart.js только нужные компоненты (tree-shaking), не `registerables`
  целиком.
- **Период:** пресеты «7 дней», «30 дней», «3 месяца», «Этот месяц»,
  «Прошлый месяц», «Год», «Всё время» + свой диапазон дат. По умолчанию –
  30 дней. Выбор периода запомнить в `localStorage` (обернуть в
  try/catch).
- **Фильтр по промокоду** – «Все» или конкретный.
- **Итоги за период** (плитки): начислено, заказов, средний чек заказа,
  выплачено (заявки в статусе 20 по `created_at`), сравнение с
  предыдущим таким же периодом (↑/↓ в процентах) – для «Всё время»
  сравнение не показывать.
- **График** – начисления по дням/неделям/месяцам (шаг выбирается
  автоматически по длине периода, с возможностью переключить вручную).
  Дни без заказов – нулём, чтобы были видны провалы. Всплески и просадки
  должны читаться сразу: столбцы начислений + линия числа заказов на
  второй оси, подсказка при наведении с датой, суммой и числом заказов.
  Цвета – из текущей палитры кабинета (Vuestic `primary` и спокойный
  второй), не кислотные.
- Под графиком – существующая таблица `CreditsList`, **отфильтрованная тем
  же периодом и промокодом** (если CreditsList фильтровать неудобно –
  передай в него уже отфильтрованные заказы; сам компонент меняй по
  минимуму).
- Пустой период – понятная заглушка «За этот период начислений нет», а не
  пустой график.
- Скрытые промокоды (`hidden_coupon_codes`) из статистики **не
  исключать**.
- Расчёты вынеси в чистые функции (например, `utils/statistics.js`), чтобы
  их можно было проверить отдельно от компонента.
- Только десктоп, но на узком экране не должно ломаться (график
  тянется по ширине).
